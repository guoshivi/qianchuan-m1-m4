# 判据清单（每条都是踩过坑才定下来的）

自动化最容易出的错不是「点不到」，而是**点到了、也以为成功了，其实什么都没发生**。
所以这里每一段都有明确的判据，脚本只看判据，不看「看起来对不对」。

> 出处都在代码注释里，这里只做索引。看到 `ABORT_*` 就是判据没过 —— **停下取证，别硬往下跑**。

## 通用三条

| 判据 | 怎么判 | 出处 |
|---|---|---|
| **判据绑账号** | 台账/断点/缓存按 `商品ID@号` 或按号分文件；反查不到号就报错，不猜 | `bridge/account.js` `bridge/bit-ledger.js` |
| **先判状态再动作** | 复用标签会保留页面状态：已勾就别再点（再点=取消），已开就别再开 | `bridge/tab-reuse.js` |
| **验证码硬停** | 认出验证码/滑块 → 立即停下移交，不自动过 | `bridge/captcha.js` |

## m1 建账

- 识别码 = `<号前缀><YYMMDD><NN>`，`NN` 由台账里该号该日的最大值 +1 得到（**单调分配**，重跑不撞码）→ `bridge/frag-code.js`
- 保本 < 5 ⇒ 目标 ROI × 0.7；保本 ≥ 5 ⇒ × 0.4（两位小数，边界 5 走 0.4）→ `bridge/roi-map.js`
- 品名解析不到就只留后缀，**不拿后缀冒充品名** → `bridge/short-title.js`

## m2 素材

- 素材目录**按商品 ID 搜索**，不写死 `~/Downloads/4`（真出现过按品名命名、换编号的情况）→ `bridge/mat-dir.js`
- 封面池按商品 ID 做种子：同品重跑结果一致，一次跑内不撞图 → `tools/video-dedup/dedup_run.py`

## m3 炮灰视频

| 环节 | 判据 |
|---|---|
| 出片 | `RENDER` 成功后才 `copyFile`；`RENDER_FAIL` 打印 stderr 最后 6 行 |
| 首帧封面 | 开头 `coverSec`（默认 0.6s）整屏商品主图 → 抖音默认封面=主图 |
| 上传 | 视频出现在创作者中心作品列表（不是「已选择文件」就算） |
| 发布 | **URL 离开发布页** 或 页面出现「发布成功」；只看到按钮变灰不算 → `bridge/bit-m3-publish.js` |

## m4 放量计划

| 环节 | 判据 | 出处 |
|---|---|---|
| 商品搜索 | 主键优先 `ID：<商品ID>` 相等；主键不可见（渠道品）才兜底「抽屉里只有一个商品ID + 行含**完整标题**」；模糊匹配一律不认 | `bridge/bit-m4-upload.js` |
| 素材抽屉 | 取**文本最长**的抽屉（`reverse().find(width>300)` 会抓到 header） | 同上 |
| 素材进池 | 页面显示 `素材 5/视频 5`；或 URL 带 `sourceFrom=createSuccess` | 同上 |
| 结束点 | 素材传完就停，**不点发布**（`--publish` 才点） | 同上 |

## 时间/频率

- 千川、联盟域按 profile 限频（默认 45s 一次导航）。不要为了「看一眼」反复导航 —— 会把自己闸死。
- ego 每个空间最多 8 个标签。同域只留一个，能复用就复用（`ego-transport.acquireTab()`）。
