# 素材去重 · cover_dedup.py 使用说明

> 链路位置：**M2 素材与去重**（员工机执行）→ 输出传 NAS → 核心机 M4/M7 使用
> 状态：✅ **本工具是去重环节的唯一权威版本**（用户 2026-09-10 确认「这份已经优化得很完美」）。
> 其他历史去重脚本（`去重鼠.py` GUI、`batch-dedup.py` 重型版）**不进体系，勿用**。

一句话：**给每个产品文件夹里的视频，统一加上封面开头 + 做肉眼不可见的轻去重 + 统一成 1080×1920**，用于规避平台判重。

---

## 1. 依赖

| 依赖 | 说明 |
|---|---|
| Python 3 | 无第三方包（只用标准库） |
| ffmpeg / ffprobe | 必须在 PATH 里：`brew install ffmpeg`（Mac）/ `apt install ffmpeg`（Linux）/ Windows 装到 PATH |

## 2. 目录约定（重要）

```
<视频根目录>/                     ← --input
├── 产品A/                        ← 子文件夹名 = 产品标识（如商品名 / 抖音 aweme_id）
│   ├── video_1.mp4
│   └── video_2.mp4               ← 每品 ≤5 条（链路约定）
└── 产品B/
    └── ...

<封面目录>/                       ← --covers
├── 产品A.jpg                     ← 文件名必须与产品文件夹名【完全一致】
└── 产品B.jpg

<输出目录>/                       ← --out（结构镜像输入）
└── 产品A/video_1.mp4
```

- 一个产品一张封面图；缺封面会打印 `NO COVER <目录名>` 并跳过该产品
- 源文件支持 `.mp4` / `.mov`（`.mov` 会统一转成 `.mp4`）

### 封面池（✅ 用户 2026-09-11 指定：以后固定放这里）

```
~/Downloads/4/image/          ← 封面池根目录（所有封面都放这）
├── 唯美风景图1-海边日落.png     ← 顶层 10 张（576×1024 或更大，均 9:16）
├── 抖音图1-黎明前的静谧.jpg
├── mjv7_20张/                 ← 20 张 1080×1920（Midjourney v7 生成，强制无人/无字/无水印）
│   ├── 唯美风景图_MJ07_01..20.jpg
│   ├── _raw/ _raw_old/ _log/  ← ⚠️ 工作目录，不算成品，扫描时一律排除
│   └── topup.py               ← 生成脚本（lovart API，--ar 9:16 --no people/text/watermark）
└── tupian/                    ← 10 张 9:16
```

- 池内合计 **40 张成品封面**（顶层 10 + mjv7_20张 20 + tupian 10）
- ⚠️ **池内 `_` 开头的目录一律不算成品封面**（`_raw` / `_raw_old` 原始 lovart 产物、`_log`、`_resolved` 解析产物）
  —— 踩过：只按精确名排除 `_raw` 时，`_raw_old/` 里 4 张旧图会混进池子被抽中
- ⚠️ **命名缺口**：`cover_dedup.py` 要求封面文件名为 `<产品文件夹名>.jpg`，而池内是
  `唯美风景图_MJ07_01.jpg` 这类通用名 —— 中间需要一层「挑一张 → 另存为 `<产品文件夹名>.jpg`」的解析
  → 已由 `dedup_run.py` 自动化（见下节），解析产物写 `~/.qc-rebuild-ego/covers-resolved/`，**不往池子里塞任何东西**
- 池内 `.png` 也能用，解析时会统一转成 1080×1920 的 `.jpg`

## 3. 用法

### 3.1 一条龙（推荐）：`dedup_run.py` 自动配封面 + 调去重

```bash
cd ~/work-douyin/fp-matrix/tools/video-dedup

# 先看会给谁配哪张（不渲染、不写盘）
python3 dedup_run.py --input ~/Downloads/default/<示例ID> --dry-run

# 就地覆盖去重（最常用）
python3 dedup_run.py --input ~/Downloads/default/<示例ID> --inplace

# 另存输出
python3 dedup_run.py --input ~/Downloads/6/default --out ~/Downloads/6/default_去重3
```

**封面绑定规则（用户 2026-09-11 定）**：按产品文件夹名做种子随机挑一张，**同一次跑不重复**
→ 同一商品重跑结果一致（可复现），一次跑内多个商品不会撞同一张。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--input` | 必填 | 素材根目录（子文件夹=产品）；**也接受直接给单个产品文件夹** |
| `--pool` | `~/Downloads/4/image` | 封面池根目录（用户指定，以后封面都放这里） |
| `--resolved` | `~/.qc-rebuild-ego/covers-resolved` | 解析产物目录（`<产品>.jpg` + `_mapping.json`），与品台账同处，不放进封面池 |
| `--out` | =`--resolved` | 输出目录（与 `--inplace` 二选一） |
| `--inplace` | 关 | 覆盖源文件 |
| `--workers` | 3 | 并发 |
| `--cover-sec` | 0.04 | 封面前置秒数 |
| `--dry-run` | — | 只打印「商品 ← 封面」映射，不处理视频 |
| `--remap` | — | 忽略已解析封面，重新抽签 |

行为要点：

- 池里若已有**精确同名**的 `<产品名>.jpg`（你手工指定）→ 优先用它，不抽签
- 已解析过的产品**默认沿用**上一张（幂等；要换用 `--remap`）
- `--out` 落在 `--input` 里面也安全（输出目录不会被当成产品，避免成品被二次去重）
- **封面池是只读的**：脚本只从池里读图，不写回池子（解析产物另存 `~/.qc-rebuild-ego/covers-resolved/`）
- 单产品文件夹模式内部会搭一层临时符号链接目录（因为 `cover_dedup.py` 只认「子文件夹=产品」）

### 3.2 直接用 `cover_dedup.py`（封面已备好同名文件时）

```bash
python3 cover_dedup.py \
  --input  /path/to/素材/<日期>/<号> \
  --covers /path/to/封面 \
  --out    /path/to/成品 \
  --workers 3
```

**覆盖模式**（处理完直接替换源文件，不写输出目录）：

```bash
python3 cover_dedup.py --input ... --covers ... --out ... --inplace
```

## 4. 参数

| 参数 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `--input` | ✅ | — | 视频根目录（子文件夹 = 产品） |
| `--covers` | ✅ | — | 封面目录（每张图命名 `<产品名>.jpg`） |
| `--out` | ✅ | — | 输出目录 |
| `--inplace` | | 关 | 覆盖模式：处理完直接替换源文件 |
| `--workers` | | 3 | 并发线程数 |
| `--cover-sec` | | 0.04 | 封面前置秒数（0.04s ≈ 1~2 帧，一闪而过） |

## 5. 每条视频做了什么（固定管线）

1. **封面前置**：封面图拼到视频开头 `cover-sec` 秒（1080×1920 静帧）
2. **统一画幅**：原视频等比放大裁切到 1080×1920
3. **随机微缩放**：`zoom 1.012~1.028` 放大后再裁回 1080×1920（lanczos）
4. **色彩微调**：`hue ±4°`、`saturation 1.01~1.035`、`brightness -0.008~0.012`、`contrast 1.005~1.025`
5. **编码**：`libx264`、`crf 20~23`、`preset fast`、`fps 30`、`yuv420p`、`+faststart`
6. **音频**：有音轨 → `adelay` 补偿封面时长 + 统一 48kHz 立体声 + `aac 128k`；无音轨 → 输出无音轨
7. **硬校验**：ffprobe 必须返回 `h264,1080,1920`，否则删掉临时文件并计失败

> 随机参数每条视频独立抽取，同一素材跑两次结果也不同（MD5 必然变化）。

## 6. 输出与退出码

```
total jobs: N
SKIP(done) <路径>        ← --out 模式下已存在，跳过
NO COVER <目录名>        ← 缺封面，跳过
FAIL <路径> + ffmpeg 尾部报错
VERIFY_FAIL <路径> <实际规格>
DONE ok=X fail=Y
```

- **有失败时退出码 = 1**，方便串进脚本/CI 判断
- `--out` 模式**幂等**：已存在的输出自动跳过，可放心重跑
- `--inplace` 模式每次都重处理（源文件即待处理素材）

## 7. 注意事项

- 临时文件写 `<目标>.tmp.mp4`，**只有通过规格校验才会落位**——不会留半成品
- 2026-09-05 起**不再写标记文件**（标记会混进成品目录碍事），重复跑靠规格校验兜底
- 封面文件名与产品文件夹名不一致 = 静默跳过（看 `NO COVER` 输出）
- 单条视频处理超时上限 900s

## 8. 典型工作流

```bash
# 1) 员工机：下载达人素材 → 按品放文件夹（每品 ≤5 条）+ 准备同名封面
```
